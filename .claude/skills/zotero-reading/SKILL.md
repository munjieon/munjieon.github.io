# Zotero에서 읽은 글 쓰기

편집장이 Zotero의 **읽을거리** 컬렉션에 넣어 둔 자료를 한 편 골라, 원문에 기대어 요약하고 PR로 올린다. 리포의 `CLAUDE.md` 규칙이 이 문서보다 앞선다.

## 0. 연결 확인

```
python3 .claude/skills/zotero-reading/scripts/zotero.py whoami
```

- 인증은 클라우드 환경의 Network secret(호스트 `api.zotero.org`, 헤더 `Zotero-API-Key`)이 붙여 준다. 키를 채팅에 달라고 하지 않는다. 로컬에서는 `ZOTERO_API_KEY` 환경 변수를 쓴다.
- 라이브러리는 키 권한으로 자동으로 고른다. 그룹이 여럿이면 `ZOTERO_LIBRARY=groups/<id>`를 지정한다.
- `403 ... agent proxy`가 나오면 이 세션의 환경이 `api.zotero.org`를 허용하지 않는 것이다. 편집장에게 프로젝트 설정에서 munjieon.github.io 환경을 고르도록 알린다. `HTTP 403`(Zotero 응답)이면 키나 권한 문제다.
- 키는 읽기 전용이다. Zotero에 태그를 달거나 항목을 옮기지 않는다.

## 1. 고르기

```
python3 .claude/skills/zotero-reading/scripts/zotero.py queue
```

`완료`는 이미 `content/notes/`의 `source.zotero`에 그 키가 있는 항목이다. 편집장이 고른 것이 없으면 `대기` 중 가장 먼저 들어온 것을 고르되, 최근 읽은 글들과 분야(음운·형태·통사·어휘·의미·문자와 문헌 등)가 겹치면 다른 분야를 먼저 고른다.

## 2. 읽기

```
zotero.py item KEY        # 메타데이터
zotero.py csl KEY         # 서지 (front matter의 source를 여기서 채운다)
zotero.py children KEY    # 첨부·노트
zotero.py fulltext ATTACHMENT_KEY > /tmp/…/fulltext.txt
zotero.py note NOTE_KEY   # 편집장 메모가 있으면
```

- 원문은 `fulltext`(Zotero가 색인한 PDF 전문)를 먼저 쓴다. `pages: n/m`에서 n<m이면 일부만 색인된 것이니 빠진 쪽을 요약하지 않는다.
- 전문이 없거나 스캔본이라 비어 있으면 `file`을 시도하고, 그래도 안 되면 편집장에게 PDF를 직접 달라고 한다. **초록이나 기억만으로 요약하지 않는다.**
- 전문 파일은 스크래치 디렉터리에 두고 리포에 넣지 않는다(저작권).

## 3. 쓰기

`archetypes/notes.md` 형식으로 `content/notes/<파일 이름>.md`를 만든다. 파일 이름은 `저자성-연도-핵심어`의 로마자 소문자. front matter의 `slug`에는 `python3 scripts/post-numbers.py next notes`가 주는 번호를 넣는다. 글 주소는 `/notes/<번호>/`가 된다(리포 `CLAUDE.md` “글 주소”).

- 독자는 언어학 개론을 들은 학부생이나 관심 많은 일반 독자다(리포 `CLAUDE.md` 문체 항목). 용어·옛 형태·문헌명은 처음 나올 때 짧게 풀고, 옛 글자가 섞인 글이면 첫머리에 짧은 “읽기 전에” 안내를 둔다. 결론에 직접 필요한 근거는 본문에, 곁가지 근거(성조형, 이본 대조, 자료 처리 과정)는 각주로 보낸다. 문체 세부는 리포 `STYLE.md`를 따른다.
- 따옴표는 늘 굽은 따옴표(“ ” ‘ ’)로 쓴다. 곧은 따옴표(" ')는 front matter·숏코드의 문법 기호와 코드에만 남긴다(리포 `CLAUDE.md` 문체 항목).

- `source`: CSL-JSON에서 옮긴다. `zotero`에는 항목 키를 넣는다. 확인되지 않은 칸은 비워 둔다.
- `세 줄 요약`: 원 자료의 결론 세 개.
- `본문 요약`: 원 자료의 짜임을 따라간다. 주장마다 쪽수를 각주로 단다(`[^p12]: 12쪽.`).
- 재구형, 용례, 반절, 한자음, 연도는 **원문에서 그대로** 옮기고 쪽수를 단다. 표기는 `ipa`, `lang`, `gloss` 숏코드로 감싼다. 원문 표기를 바꾸어 적었으면 그렇다고 밝힌다.
- 원 자료가 다른 학설과 맞서 있으면, 원 자료가 소개한 상대 학설도 원 자료의 말로 적는다.
- `주목할 부분`: 이곳에만 문지언의 해석을 쓴다. 다른 문헌을 끌어오면 그 문헌을 실제로 확인한 경우에만 인용한다.
- `참고문헌`: 원 자료와 실제로 인용한 문헌만.
- `draft: false`로 두되, 머지는 편집장이 한다.

## 4. 별도 검토 패스

쓴 사람과 다른 눈으로 본다. 새 컨텍스트(서브에이전트 또는 따로 한 번 더)에서 원문 전문과 초안만 주고 다음을 따진다.

1. 요약의 각 주장이 원문 해당 쪽에 실제로 있는가. 없는 말이 들어갔는가.
2. 재구형·용례·한자·연도가 원문과 글자 하나까지 같은가.
3. 해석이 `주목할 부분` 밖으로 새어 나왔는가.
4. 원 자료의 핵심 논점 가운데 빠진 것이 있는가.
5. 숏코드, 합니다체, 굽은 따옴표, 용어 풀이, `STYLE.md`의 쓰지 않는 버릇(‘A가 아니라 B’, 줄표, 단문 연쇄 등). 독자(언어학 개론을 들은 학부생이나 관심 많은 일반 독자)가 본문만 읽고 따라올 수 있는가: 풀이 없는 용어·옛 형태·문헌명, 각주로 보낼 만큼 빽빽한 대목, 풀이에 원 자료에 없는 사실이 들어갔는지.

지적을 고친 뒤, 고치지 않은 지적은 이유와 함께 PR 본문에 남긴다.

## 5. 편집장 손질

PR을 열기 전에 `.claude/skills/editor-pass/SKILL.md` 절차를 따른다. 원고를 `post/<파일 이름>` 브랜치에 푸시하고, 손질본(Claude 문서)을 편집장에게 내주고, 편집장이 “다 고쳤어”라고 하면 고친 것을 원고에 옮긴다. 편집장이 요약 부분에 해석을 덧붙였으면 `주목할 부분`이나 편집장 덧붙임 상자로 옮길지 묻는다(술이부작).

## 6. 올리기

`post/<파일 이름>` 브랜치(세션이 다른 브랜치를 지정하면 그 브랜치)에서 글 한 편당 PR 하나. PR 본문에는 원 자료 서지, Zotero 키, 전문 색인 쪽수, 검토 패스 결과, 편집장 손질 요약(editor-pass 6단계)을 적는다. 빌드는 GitHub Actions가 확인한다.
