# 편집장 손질

문지언이 쓴 초안은 PR로 가기 전에 편집장이 먼저 읽고 고친다. 표현을 다듬고, 자기 말을 덧붙이고, 틀린 데를 바로잡는다. 에이전트는 손질본을 내주고, 편집장이 고친 것을 원고에 옮기고, 집 규칙을 맞춘 뒤 PR을 연다. 리포의 `CLAUDE.md` 규칙이 이 문서보다 앞선다.

세 갈래(읽은 글, 쓴 글, 찾은 글)에 모두 쓰고, 이미 실린 글을 고칠 때도 같다. 편집장이 “손질 없이 바로 올려”라고 한 글만 이 단계를 건너뛴다.

## 흐름

1. 초안 완성: 각 스킬의 쓰기와 별도 검토 패스까지 마친다.
2. 원고 보관: 원고(.md)를 글 브랜치에 커밋하고 푸시한다. PR은 아직 열지 않는다.
3. 손질본 내기: 편집장이 고칠 문서를 만들어 링크를 준다.
4. 편집장 손질: 편집장이 문서에서 고치고 “다 고쳤어”라고 한다.
5. 옮기기: 고친 것을 원고에 옮기고 집 규칙을 맞춘다.
6. PR: 손질 내역을 PR 본문에 적고 PR을 연다. 머지는 편집장이 “머지해”라고 할 때만 한다.

## 2. 원고 보관

- 새 글은 `post/<slug>`(찾은 글은 `post/finds-<YYYY-MM-DD>`), 이미 실린 글을 고칠 때는 `edit/<slug>` 브랜치. 세션이 다른 브랜치를 지정하면 그 브랜치를 쓴다.
- 손질이 며칠 걸려 스레드가 바뀌어도 원고는 브랜치에서 이어받는다. 프로젝트 메모리에 “손질 중인 글: <글 제목>, 브랜치, 문서 링크”를 한 줄 남기고, PR을 열면 지운다.

## 3. 손질본 내기

```
python3 .claude/skills/editor-pass/scripts/to_doc.py content/<갈래>/<파일>.md > $SCRATCH/doc.md
```

이 변환은 숏코드를 걷어 내고 예문은 코드 칸으로, 찾은 글은 항목별 “요약 / 문지언 / 편집장” 줄로 바꾼다. 결과를 **Claude 문서**(Claude Docs)로 만든다.

- 문서 제목: `손질본: <글 제목>`.
- 맨 위에 손질 안내를 짧게 둔다(아래 문구를 그대로 써도 된다). 그 아래에 원고 전문.
- 문서를 만든 직후의 판(rev)을 기록해 둔다. 5단계에서 이 판과 비교한다.
- 편집장에게 링크와 함께 “다 고치시면 ‘다 고쳤어’라고 해 주세요” 한 줄을 보낸다.

손질 안내 문구:

> 마음대로 고치시면 됩니다. 표현을 바꾸셔도, 문단을 지우거나 옮기셔도 됩니다.
> - 편집장 이름으로 따로 보이게 덧붙이고 싶은 말은 문단 앞에 [편집장]을 붙여 주세요. 글에 “편집장 덧붙임” 상자로 실립니다(이름은 싣지 않습니다). 그냥 본문에 섞어 쓰신 말은 문지언의 글로 실립니다.
> - 확신이 없거나 묻고 싶은 곳은 댓글로 남겨 주세요.
> - [^p12] 같은 표시는 각주 자리입니다. 지우지 않으면 됩니다. 예문 칸은 줄 구성(원문 / 형태 분석 / 낱말 뜻 / 번역)을 지켜 주세요.
> - 따옴표 모양, 한자·일본어 표지, 각주 꼴은 제가 맞춥니다.

Claude 문서 도구가 없는 실행(예: 커넥터 없는 정기 실행)에서는 손질본을 만들지 말고 `post/…` 브랜치를 **초안(draft) PR**로 연 뒤, 편집장에게 “Claude 문서를 만들 수 없어 초안 PR로 올렸습니다. 이 스레드에서 ‘손질본 줘’라고 하시면 문서로 드립니다”라고 알린다. 초안 PR은 머지 검토 대상이 아니다. 편집장이 손질을 마치면 6단계에서 검토용(ready for review)으로 바꾼다.

## 4. 편집장 손질을 기다리는 동안

- 기다리는 동안 원고를 고치지 않는다. 고칠 것이 생기면 문서에 댓글로 제안한다.
- 편집장 댓글에 질문이 있으면 그 댓글 스레드에서 답한다. 고쳐 달라는 댓글이면 문서에서 고치고 같은 스레드에 무엇을 고쳤는지 적는다.

## 5. 옮기기

“다 고쳤어”가 오면 3단계에서 기록한 판과 지금 판을 비교해 편집장이 바꾼 곳을 모두 뽑는다(문서의 이전 판 읽기 `atRev`, 또는 `sinceRev`). 바뀐 곳마다 원고 .md의 같은 자리에 손으로 옮긴다. 문서 전체를 원고에 덮어쓰지 않는다.

옮길 때 지킬 것:

1. **편집장의 말이 이긴다.** 편집장이 쓴 표현, 순서, 삭제는 그대로 따른다. 에이전트가 더 낫다고 생각하는 표현으로 바꾸지 않는다. 다르게 하고 싶으면 PR 전에 묻는다.
2. **기계적인 집 규칙만 에이전트가 맞춘다.** 굽은 따옴표(“ ” ‘ ’), 한자·일본어의 `lang` 숏코드, IPA·재구형의 `ipa`, 예문의 `gloss`, 각주 꼴, 띄어쓰기·맞춤법의 명백한 오타. 숏코드는 3단계에서 걷어 낸 자리에 되살린다.
3. **[편집장] 문단**은 `{{< editor >}} … {{< /editor >}}`로 감싼다. 찾은 글에서는 그 항목의 `editor:` 칸에 넣는다. 편집장의 이름은 어디에도 넣지 않는다.
4. **편집장이 덧붙인 사실적 주장에 출처가 없으면** 지어 붙이지 않는다. 쓴 글처럼 각주가 필요한 갈래면 편집장에게 출처를 묻고, 답을 받기 전에는 PR 본문 “확인할 것”에 적는다. 편집장이 알려 준 출처도 원 자료에서 확인한 뒤 각주로 단다.
5. **갈래의 규칙과 부딪히면** 고치지 말고 알린다. 예를 들어 읽은 글의 요약 부분에 해석이 들어왔으면 “눈여겨볼 지점”이나 편집장 덧붙임 상자로 옮길지 묻는다. 문체가 합니다체가 아닌 문단, 독자 수준(언어학 개론을 들은 학부생이나 관심 많은 일반 독자)에 비해 풀이가 빠진 용어도 제안만 한다.
6. 편집장 손질로 뜻이 바뀐 곳이 각주나 요약·front matter(`description`, `tags`)와 어긋나면 그쪽도 맞추고 PR 본문에 적는다.
7. 다 옮긴 뒤 원고와 문서를 한 번 더 나란히 읽어 빠진 손질이 없는지 본다. 찾은 글은 `finds.py check`를 다시 돌린다.

옮기다 물을 것이 생기면 질문을 한 번에 모아 묻는다. 기계적인 것만 남았으면 묻지 않고 6단계로 간다.

## 6. PR

- 이미 실린 글을 고친 PR이면 front matter에 `lastmod: <오늘 날짜>`를 넣는다.
- PR 본문에 적는 것(각 스킬이 요구하는 내용에 더해):
  - 손질본 문서 링크.
  - 편집장 손질 요약: 몇 곳을 고쳤는지, 덧붙임 상자 몇 개인지.
  - 에이전트가 덧붙여 바꾼 것: 집 규칙 맞춤 외에 바꾼 것이 있으면 하나하나.
  - 확인할 것: 출처를 기다리는 주장, 묻고 남은 제안.
- 3단계에서 초안 PR로 갔으면 같은 PR을 검토용으로 바꾸고 본문을 위처럼 고친다.
- PR을 연 뒤 편집장에게 PR 링크와 한두 줄 요약을 보낸다. PR에서 마지막으로 보고 “머지해”라고 하면 머지한다.

## 이미 실린 글 고치기

편집장이 “<글> 고칠래”라고 하면 main의 그 글로 위 흐름을 그대로 탄다(브랜치 `edit/<slug>`). 고칠 글이 정해지지 않았으면 실린 글 목록(제목, 갈래, 날짜)을 보여 주고 고르게 한다.
